ToTchar 2002

 

"ToTchar" ist ein kleines Tool, das Ihnen viel Arbeit abnehmen kann. Sie kennen wahrscheinlich die "Generic-Text Routine Mapping", die in der Header-Datei "Tchar.h" definiert sind, kennen. Diese Makros erlauben Code zu schreiben, der als Unicode oder als Multibyte-Charaker kompiliert werden kann. Sie haben vielleicht noch alten Code, den Sie Umstellen wollen. Die Umstellung per Hand zu erledigen ist eine mühsame Aufgabe. Der Grund, warum ich dieses Programm entwickelt habe, war der daß ich die "alten" Schreibweisen wie z.B. "strchr" gewohnt bin und mir die "neuen" Formen auch etwas seltsam erschienen. Mit diesem Tool kann ich weiterhin so wie ich es gewohnt bin codieren, aber doch die Vorzüge der "Generic-Text Routine Mapping-Makros" genießen.

Es sei hier ausdrücklich darauf hingewiesen, daß dieses Programm nicht eine Vollständige Umstellung ermöglicht. Sie müssen den Code gegebenenfalls noch einmal durchgehen.

Es muß bei Parameterübergaben von Funktionen immer darauf geachtet werden, ob die Anzahl der Bytes oder die Anzahl der Charakters mitgegeben werden muß.

Hier ein Beispiel:

 

GetModuleFileName(NULL, szFile, MAX_PATH);

 

In diesem Fall wird nach der Anzahl der Charakters gefragt und Sie übergeben die Anzahl der Charakters mit der Funktion.

Wenn aber eine Funktion die Anzahl in Bytes benötigt. Wie z.B.

 

lpszFile = (LPTSTR)HeapAlloc(hHeap,0L,MAX_PATH * sizeof(TCHAR));

 

müssen Sie die Anzahl der Charakters mal die Größe von TCHAR übergeben. In einer nicht-Unicode-Anwendung hat ein Charakter eine Größe von einem Byte, in einem Unicode-Programm eine Größe von 32-Bit.

Dieser Punkt ist sehr wichtig; das kann leider nicht von diesem Programm in diesem Umfang geleistet werden.

Wenn Sie Text in die Zwischenablage kopieren wollen, sollten Sie folgenden Code verwenden:

 

#ifdef UNICODE

SetClipboardData(CF_UNICODETEXT, hText);

#else

SetClipboardData(CF_TEXT, hText)

#endif //UNICODE

 

Das wird auch nicht von diesem Tool geleistet.

 

Bevor das Programm eine Veränderung an dem Quellencode vornimmt, wird von diesem eine Backup-Datei erstellt. Ich empfehle folgende Vorgehensweise.

Wählen Sie eine Datei (oder auch mehrere) aus und führen Sie die Konvertierung aus. Vergleichen Sie die Backup- und Originaldatei mit "Windiff" (Dieses Tool gehört zum Visual C++-Paket), wenn Sie fehlerhafte Umwandlungen oder sonstige Bugs entdecken, stellen Sie die ursprüngliche Datei wieder her und schreiben mir, mit einer Beschreibung des Bugs.

Dieses Programm wurde zwar ausgiebig getestet, es kann aber keine Fehlerfreiheit vorausgesetzt werden, da es dabei um ein relativ komplexes Programm handelt und recht fehleranfällig ist. Sie brauchen jetzt keine Angst zu haben, es wird immer eine Backup-Datei angelegt. Sollte dieser Vorgang scheitern, wird die Konvertierung abgebrochen, so daß die Originaldatei erhalten bleibt.

 

Sie können dieses Programm für Freeware-Programme und Programme für den privaten Gebrauch benutzen.
